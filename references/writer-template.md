# Writer 强制输出骨架与硬性约束

> 本文件是 deep-research-report skill 的 Writer 强制输出模板。每个 `chapter_writer_agent` 在执行 Phase B 写作前**必须**先读取本文件。
>
> **性质**：硬性阻断层——本文件定义的规则是"不遵守就阻断"级别的硬约束，违反任何一条即触发 `chapter_auditor_agent` 的 REVISE 裁决。

---

## 一、分章文件整体结构骨架

每个分章文件的 Markdown 结构必须严格遵循以下骨架。**不得增删或调换骨架中的任何一个结构性元素**。

```markdown
> **本章结论**：用 3-5 句话概括本章最重要的发现或判断。

---

### <H3 节标题>

[正文内容，以论证性叙事展开。每个关键判断后使用 [SRC-XXX] 格式标注引用。]

[更多 H3 节...]

[最后一个 H3 节的收尾段落：在该节正常论证内容的基础上，自然收束出至少 1 句局限说明（本章分析的边界/未覆盖维度/假设脆弱性）与至少 2 句章间过渡（总结本章论证落脚点 + 以内容层面衔接下一章，非坐标指路式的"详见第X章"）。不要求另起 H3，不要求 blockquote 字面标签——融入收尾段落的正常论述即可。]
```

**骨架要素清单**（缺一不可）：

| 序号 | 要素 | 层级 | 是否必须 | 说明 |
|------|------|------|---------|------|
| 1 | `> **本章结论**：` | blockquote | **必须** | 章首唯一结论标记，3-5 句，加粗字面标签 `**本章结论**：`，不占 heading 层级 |
| 2 | 分隔线 | `---` | **必须** | 结论与正文之间的分隔 |
| 3 | 正文节 | H3 × N | **必须** | 按大纲 YAML `section_title` 展开论证，标题纯文字不加编号 |
| 4 | 局限说明 | 融入最后一节收尾段落 | **必须（语义）** | 至少 1 句，不要求独立 H3、不要求独立成段，能被读者识别出"作者承认了本章分析的哪个边界"即可 |
| 5 | 章间过渡 | 融入最后一节收尾段落 | **必须（语义）** | 至少 2 句，不要求 blockquote 字面标签；若报告写法偏好用引用块突出本章小结，允许保留，但这只是可选排版选择 |

> **不再强制独立 H3"本章对主论点的贡献"**：局限说明与章间过渡是**语义要求**，不是**结构容器要求**——判定标准是"读者能否识别出这两类内容"，而非"是否存在对应标题/引用块"。把它们单独摘出为一个总结性 H3，容易变成对写作过程本身的复述（"本章通过...确立了..."），而非论证内容本身；正确做法是让它们成为最后一个正文节收尾论证的自然延伸。

## 二、章首结构硬性要求

### 2.1 章首必须是结论 blockquote

分章文件的第一个非空内容必须是：

```
> **本章结论**：[3-5 句核心判断]
```

分章文件中**绝对禁止使用 H2**。H2 仅由 merge 管道在拼接时作为章容器插入。

**禁止的变体**（以下任何一种出现在分章文件章首即触发 C2 阻断）：

- `## 本章结论`（旧 H2 格式，已废弃）
- `## 本章摘要`
- `## 本章概览`
- `## 核心发现`
- `## 本章要点`
- `## 结论`
- `## 主要结论`
- 任何其他语义相近但措辞不同的 H2
- `> **本章摘要**：`
- `> **本章概览**：`
- `> **核心发现**：`
- 任何其他语义相近但措辞不同的 blockquote 加粗标签

### 2.2 禁止 H2 装饰性副标题

**绝对禁止**在分章文件中出现以下模式的 H2：

- `## ——副标题文字`
- `## —— 副标题文字`
- `## 主标题 —— 副标题`
- 任何以 `——`（破折号）连接副标题的 H2

Writer 不得自行判断"美观"而添加装饰性副标题。每个 H2 恰好表达一个结构层级，不需要副标题来补充说明。

## 三、标题层级硬性规定

### 3.1 层级映射（不可协商）

| Markdown 层级 | 对应的大纲结构 | 编号归属 | 说明 |
|---------------|---------------|---------|------|
| `###` (H3) | 节 | 转换器自动加"X.Y" | **Writer 只写到本级**。分章文件中无 H2——H2（章容器）由 `finalizer_agent` 在合并时插入。标题文本必须是纯文字 |
| `####` (H4) | 小节 | 转换器自动加"X.Y.Z" | 标题文本必须是纯文字 |

**合并后层级映射**（供 Writer 理解最终效果，非写作要求）：

| 分章草稿 | 合并后 | docx 样式 |
|---------|--------|----------|
| （不写章容器） | `## 第 X 章：<chapter_title>` | `Heading 1` (CHAPTER) |
| `> **本章结论**：...` (blockquote) | `> **本章结论**：...` (blockquote) | `Normal`（非 heading） |
| `### <section_title>` | `### <section_title>` | `Heading 2` (SECTION) |
| `#### <subsection_title>` | `#### <subsection_title>` | `Heading 3` (SUBSECTION) |

> **2026-08-03 变更**：分章文件不再以 `## 本章结论` 起始。旧版中 merge 管道对分章文件执行 `_demote_headings()` 全部标题下沉一级（H2→H3, H3→H4），以化解"双相邻 H2"问题。新版 Writer 不写 H2，合并不再需要 demotion——Writer 产出层级直接就是合并后正确层级。

### 3.2 禁止用粗体伪标题替代 H3/H4

**绝对禁止**以下模式：

```markdown
❌ **技术架构设计**      ← 应该用 ### 技术架构设计
❌ **1. 系统组成**       ← 应该用 ### 系统组成
❌ **（一）功能模块**    ← 应该用 ### 功能模块
```

判定规则：如正文中出现连续 ≥3 行以 `**` 开头且独占一行的粗体文本（即 `^\\*\\*[^*]+\\*\\*\\s*$`），视为粗体伪标题违规。应用 `###` 或 `####` 替代。

### 3.3 标题只写纯文字

正文各级标题（H2/H3/H4）**必须只写纯文字**，不添加任何以下内容：

- 数字编号（如 `1.1`、`一、`、`（一）`）
- 中文数字前缀（如 `第一章`、`第一节`）
- 页数预算（如 `（约3页）`）
- 任何形式的编号前缀或后缀

编号由阶段 9 转换器自动生成。Writer 的任务是提供**纯文字标题文本**。

## 四、禁止内容清单（F1-F8, F10）

以下 10 类内容**绝对禁止**出现在分章文件草稿正文中。审计 Agent 会使用 `contract_check.py` 的 C2/C5/C6/C7/C8/C9 规则和 `term_consistency_check.py` 脚本逐项检测（命中即阻断）；`contract_check.py` 另有 C10/C11 两项对应 F7/F8 的检测（详见下表说明），当前处于**第一阶段观察期**——只计数、不阻断，尚未纳入自动阻断范围，Writer 仍须按下表规则自律遵守。

| 编号 | 禁止内容 | 检测正则/方法 | 阻断级别 | 说明 |
|------|---------|-------------|---------|------|
| **F1** | 输出隔离标记残留 | `\[AGENT-OUTPUT-START(:[0-9a-f]{6,16})?\]` / `\[AGENT-OUTPUT-END(:[0-9a-f]{6,16})?\]`（nonce 后缀可选，两种形式均检测） | FATAL | 包括 `[AGENT-OUTPUT-START]`、`[AGENT-OUTPUT-END]`（含或不含 `:<nonce>` 后缀）及中间的所有 Agent 名称标记。这些标记是工作流协作元数据，不是正文内容 |
| **F2** | 局部参考文献节 | `^###\s+参考文献` 或 `^##\s+参考文献` | FATAL | 每章末尾不得出现独立的"参考文献"节。全报告统一参考文献由 `finalizer_agent` 在阶段 9 统一生成 |
| **F3** | 字数统计残留 | `全文约.*字`、`本章字数`、`本章字数.*:.*\d+`、`写作者自声明` | **FATAL**（2026-08-03 升级：自声明已移至独立文件 `research/claims/各章节自声明.md`，章草稿中不应再出现任何自声明相关文字） | 包括"全文约 XXXX 字""本章字数约 XXXX"、`### 写作者自声明（第 X 章）` 等。这些内容唯一合法位置是 `research/claims/各章节自声明.md` |
| **F4** | 篇幅预算元信息 | `建议印刷页数`、`篇幅预算`、`本章约.*页` | **FATAL**（2026-08-03 升级：与 F3 同机制——篇幅预算类元信息不应出现在正文中，仅存于大纲 outline.md） | 大纲阶段的内部标注，不应进入正文 |
| **F5** | "本章摘要/概览"等变体 | `^##\s+本章(摘要|概览|要点|核心)` 等 / blockquote 标签变体 `^>\s*\*\*本章(摘要|概览|要点|核心)` | FATAL | 分章文件章首只允许 `> **本章结论**：` blockquote。禁止任何 H2 变体标题（已整体废弃 H2）以及禁止的 blockquote 加粗标签变体 |
| **F6** | 装饰性副标题 | `^##\s+——.+` 或 `^##\s+.*——.*` | FATAL | 任何包含破折号副标题的 H2 |
| **F7** | 信源分级前缀 | `\[A\]`、`\[B\]`、`\[C\]`、`\[D\]` 出现在参考文献条目中 | **观察期非阻塞**（`contract_check.py` C10，match `^\s*\[[ABCD]\]`，只计数不判负） | 信源分级是内部质控工具，不应出现在读者输出中。目标仍是 FATAL——第一阶段先收集真实报告语料的命中分布以排除误报，Writer 仍须自律避免写入 |
| **F8** | claim_id 泄露 | `\[CM\d{3}\]`、`\[CASE-\d{2}\]`（非引用上下文中） | **观察期非阻塞**（`contract_check.py` C11，match `\[[A-Z]{1,3}\d{3}\]`，只计数不判负） | claim_id 是台账主键，读者看到的应是上标编号 `[N]`。目标仍是 FATAL——第一阶段先收集真实报告语料的命中分布以排除误报，Writer 仍须自律避免写入 |
| **F10** | 术语不一致 | 使用 glossary 中 `banned_forms` 的禁止变体，或在无标注情况下使用 `aliases` 中的简称 | WARN（阶段7逐章）/ FATAL（阶段9终稿） | 所有原创概念的表述必须与 `research/glossary.md` 一致。Writer 必须逐字使用 preferred_form，不得使用 banned_forms。检测方式：`scripts/term_consistency_check.py` |

> **F1（输出隔离标记）特别说明**：Writer 的产出在交给 orchestrator 时，orchestrator 会提取 `[AGENT-OUTPUT-START]`...`[AGENT-OUTPUT-END]`（或带 nonce 后缀的 `[AGENT-OUTPUT-START:<hex>]`...`[AGENT-OUTPUT-END:<hex>]`）之间的**正文**内容并落盘为分章文件。如果落盘后的分章文件仍然包含这些标记行（任一形式），说明 orchestrator 提取环节有遗漏、或 Writer 在正文内部再次写入了这些标记。无论哪种原因，标记出现在分章文件中即为 F1 违规。
>
> **⚡ 2026-08-03 修订**：写作者自声明已从分章文件移至独立文件 `research/claims/各章节自声明.md`，因此不再需要独立的 `chapter_writer_agent_selfclaim` 标记对——Writer 只使用一对输出隔离标记包裹正文，自声明通过 Write/Edit 工具直接写入独立文件。旧方案中 `[AGENT-OUTPUT-START] chapter_writer_agent_selfclaim` 标记已废弃。

## 五、引用格式硬性规定

### 5.1 唯一工作格式：`[SRC-XXX]`

Writer 在分章文件正文中引用来源时，**只使用** `[SRC-XXX]` 格式（XXX 为 `source-index.csv` 中的来源编号，如 `SRC-001`、`SRC-042`）。

**允许的引用格式**：

```markdown
✅ 据某机构2025年报告[SRC-001]，市场增长率达到240%
✅ 多项研究[SRC-003,SRC-007,SRC-012]均指出这一趋势
✅ 该技术已在多个场景验证[SRC-005]
```

**绝对禁止的引用格式**：

| 禁止格式 | 反例 | 说明 |
|---------|------|------|
| 纯数字引用 | `[1]`、`[12]`、`^[5]^` | 数字编号由 `finalizer_agent` 在阶段 9 统一分配，Writer 不得自行编号 |
| 斜杠分隔 SRC | `[SRC-001/026]`、`[SRC-003/007/012]` | 多来源用逗号分隔，不用斜杠。转换脚本不支持斜杠语法 |
| S 变体 | `[S001]`、`[S-001]` | 必须用 `SRC-` 前缀，不得省略或变体 |
| 局部编号体系 | `[1]` 在文末自建参考文献列表 | Writer 不得创建局部参考文献节（F2），不得自行分配编号 |

### 5.2 逗号分隔多引用

同时引用多个来源时，用**逗号 + 空格**分隔：

```
✅ [SRC-003, SRC-007, SRC-012]
❌ [SRC-003/SRC-007/SRC-012]
❌ [SRC-003 SRC-007 SRC-012]
```

### 5.3 Writer 不产出参考文献节

Writer 的职责边界**不包括**生成参考文献列表。每章末尾不出现 `## 参考文献` 或 `### 参考文献` 节。全报告统一参考文献由 `finalizer_agent` 在阶段 9 通过 `convert_references.py` 统一生成。

### 5.4 引用生命周期

```
阶段 2 (source_collector): SRC-XXX 在 source-index.csv 中登记
阶段 7 (chapter_writer):   正文中用 [SRC-XXX] 引用 ← 唯一工作格式
阶段 9 (finalizer):        convert_references.py 将 [SRC-XXX] → [N] + 生成统一参考文献
阶段 9 (交付):             最终文档中只有 [N] 纯数字引用
```

Writer 只关心前两步。`[SRC-XXX]` → `[N]` 的转换是 `finalizer_agent` 的责任，Writer 不要越界执行。

## 六、写作者自声明（元数据块）——独立文件，不入章草稿

写作者自声明**不再放入分章草稿文件**。Writer 在完成当前章草稿后，必须将自声明**追加写入项目统一的独立文件中**：

```
research/claims/各章节自声明.md
```

该文件为项目级审计中间数据，各章 Writer 均向同一文件追加条目，供 `chapter_auditor_agent` 读取比对。**分章草稿文件（`research/drafts/chXX-*.md`）中不得出现任何自声明标题或内容——它们只包含正文。**

### 各章节自声明.md 文件格式

```markdown
# 各章节写作者自声明

> 本文件由各章 chapter_writer_agent 逐章追加写入，供 chapter_auditor_agent 审计比对。
> 最终交付文档中不应出现本文件的任何内容。

---

## 第 X 章：<章节标题>

- **文件**：`research/drafts/chXX-<描述>.md`
- **本章字数（估）**：约 N 字
- **图片引用数**：M（图号列表：图X-1, 图X-2）
- **表格数**：K
- **引用的 card_id**：CASE-01, TECH-03, ...
- **已回填 used_in_chapter 的卡片**：CASE-01(X), TECH-03(X), ...
- **素材缺口标记**：[素材缺口] 出现 0/若干处（列位置）
- **写作日期**：YYYY-MM-DD
```

### Writer 操作方式

Writer 在完成草稿正文落盘后，使用 Write/Edit 工具将上述格式的自声明条目**追加**到 `research/claims/各章节自声明.md` 文件末尾（`## 第 X 章：...` 为一个完整的章节级区块）。对于后续章节（如修订），直接**原地更新**对应章节的区块内容而非重复追加。

> **设计理由**（2026-08-03 修订）：旧方案要求自声明包裹在 AGENT-OUTPUT 标记内嵌入各章草稿末尾，导致两个问题——(a) orchestrator 提取标记后落盘的草稿文件仍含有未标记包裹的自声明文字（即"污染正文"），阶段 9 需要额外剥离步骤（R-12 兜底规则）；(b) 自声明本属审计中间数据，不应与读者可见的正文共处同一文件。新方案将审计元数据与正文物理分离，从根源消除污染风险，同时 `contract_check.py` C8 可将"本章字数"等残留关键词的严重度从 WARN 提升为 FATAL——因为它们不再有任何合法出现在章草稿中的理由。
