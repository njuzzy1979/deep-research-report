## C. 领域适配指南

当用户的研究主题属于特定领域时，按以下规则直接替换框架参数。领域明确时自动应用，领域不明确时在阶段 1 确认。

### 适配 1：替换可信度 A/B 级来源列表

在阶段 1 确认领域后，将对应来源列表写入 `source-index.csv`：

| 领域 | A 级（官方/权威）示例 | B 级（高公信力）示例 |
|------|---------------------|---------------------|
| 医疗/生物 | FDA、WHO、NEJM、Lancet | NIH、CDC、PubMed 索引期刊 |
| 金融/经济 | SEC、央行、审计报告、上市公司年报 | Bloomberg、FT、WSJ |
| 军事/国防 | 国防白皮书、DOD 官方公告、国际条约 | Jane's、RUSI、CSIS |
| 科技/IT | 原始论文（arXiv/ACM/IEEE）、专利、标准（ISO/W3C） | MIT Tech Review、IEEE Spectrum |

> 用户未提供领域特定列表时，使用阶段 2.1 的通用标准（A=官方文件/法规/论文/专利，B=高公信力媒体/权威期刊）。

### 适配 2：替换架构分析维度

根据主题从下方映射表选择，替换阶段 1.3 的通用架构维度：
- **企业/产业分析**：商业模式架构 / 技术架构 / 数据架构 / 组织架构 / 竞争架构
- **公共政策**：法律架构 / 行政架构 / 财政架构 / 社会影响架构 / 执行架构
- **技术评估**：系统架构 / 数据架构 / 安全架构 / 部署架构 / 演进架构

### 适配 3：替换需求/变化分层

根据主题从下方映射表选择变化分层：
- **企业战略**：战术调整（周）/ 战略调整（月）/ 转型（年）
- **技术产品**：热修复（小时-天）/ 功能迭代（周-月）/ 架构升级（月-季）
- **公共政策**：紧急措施（天）/ 行政令（周-月）/ 立法（月-年）

### 适配 4：替换闭环模型

根据主题从下方映射表选择核心闭环：
- **军事**：感知 → 认知 → 决策 → 执行 → 反馈
- **企业**：市场信号 → 战略调整 → 产品研发 → 上市验证 → 效果反馈
- **技术**：需求 → 设计 → 开发 → 测试 → 部署 → 监控 → 迭代
- **政策**：问题识别 → 方案设计 → 试点 → 评估 → 推广/调整

## D. 分报告类型行文要点（读者视角 + 最易踩的陷阱）

> 本节把各类型"读者期待的行文"与"最易踩的过程外泄陷阱"落成可对照的写作要点，是 `writing-standards.md` 标准 0（前台/后台分离）在各报告类型上的具体化。写作 Agent 按当前 `struct_template` 查阅对应条目；审计/红队按此核对类型专属的过程外泄。**跨类型公共基线**见文末"E. 成熟专业判断陈述的五条特征"。

### D.1 立项报告 / 可行性研究（proposal）

- **读者（评审专家/立项委员会）期待**：结论先行的**判断陈述**（"本项目技术可行，理由有三"）；技术指标以可考核形式给出；创新点是**断言 + 对比锚点**（见 `writing-standards.md` 标准 14 补充），而非"我们如何论证自己有创新"。评审看的是"你能不能做成、做到什么程度"，不是你的证据链内部如何取舍。
- **最易踩的陷阱**：把"证据强度自评"当成严谨性表演（如大段说明"类比迁移法是四类方法中最弱的一环""119 条核验记录中风险性判断占相当比例"）。承认边界是对的（标准 11），但边界说明应是**每章末尾 1-2 句的收敛**，而不是让方法论不确定性的自我剖白反复出现在摘要、前言、每一节。立项报告的边界说明要"可信而克制"，不能喧宾夺主。
- **规范锚点**：可研通行结构（项目概况→必要性→技术方案→指标→进度→效益→风险）本身即 answer-first；科技计划项目管理办法类文件对可研的要求是"结论明确、指标可考核"。

### D.2 深度研究报告 / 白皮书 / 行业分析（research，默认）

- **读者期待**：机制导向的分析叙事，每章结论先行，证据融入叙述（"泰国 BEV 销量同比增长 240%[6]，叠加充电桩三倍扩张，指向结构性而非补贴驱动的增长"），而不是"我核验了这个数字、所以可信、所以我用它"。标志是**每节一个加粗的判断句 + 支撑**。
- **最易踩的陷阱**：把交叉验证过程写进正文（"X 来源说 2 月 24 日，Y 来源说 2 月 26 日，此处取 X"）。这类取舍应沉到脚注或直接只写采用值（见标准 1 补充）。

### D.3 政策分析报告（policy）

- **读者（决策者/政策相关方）期待**：条文解读要"注明条款编号和出处"（可追溯）但结论化呈现；利益相关方分析给出**受益/受损/中立三分判断**，而非罗列分析过程。决策者要的是清晰的影响判断，忌"和稀泥式过程叙述"。
- **最易踩的陷阱**：把"这条判断来自单一 C 级行业报告转引、尚无交叉验证"这类元评论反复插入（如概念界定处每提一次就复述一遍其证据脆弱性）。可以标注证据局限，但要放在"研究方法与边界"的**集中位置**，不是每次提到该概念都复述。

### D.4 技术评估 / 选型报告（tech-eval）

- **读者（技术决策者）期待**：明确的选型判断 + 可操作的决策条件（正例："首选 TiDB，但最终决策必须在 4 周 PoC 之后"）。评测方法论要声明基准与度量，但**方法论声明集中在方法章**，结论章只给判断和条件。
- **最易踩的陷阱**：把"没有独立第三方基准、厂商数据有方法学问题"作为免责声明散布全文。这类甄别结论应集中在"数据可信度甄别"一节讲透一次，正文引用具体数字时只需一个限定词。

### D.5 快速简报（brief）

- **读者期待**：极致的 answer-first，通篇是判断和行动项。简报**完全不应出现任何过程/核验痕迹**，也不应出现前向引用坐标指路（限额 = 0<!-- linkage-const:forward_ref_limit_brief:0 -->，见 `stage-7-writing.md` §7.2）。
- **最易踩的陷阱**：因走单 Agent 极速档、缺审计，过程痕迹反而更易残留。简报档靠 `writing-standards.md` 标准 0 / `stage-7-writing.md` §7.0 四铁律的写作侧规则约束兜底。

### E. 成熟专业判断陈述的五条特征（跨类型公共基线）

用户最核心的诉求"读到成熟的专业判断陈述，而非作者的思考过程/间接引用痕迹"，操作化为以下五条可判定特征，适用于所有报告类型（与 `writing-standards.md` 标准 0 同源）：

1. **结论先行**：段落/小节首句是判断，不是背景或证据铺陈。
2. **证据融入而非外置**：数据/来源作为判断的支撑，通过上标编号 `[N]` 嵌入句中。读者通过编号在文末参考文献列表中查到完整来源信息。来源细节不作为正文的叙事对象。
3. **无编辑部过程**：正文不出现"本报告采用 X 不采用 Y""此处取 X 数字""证据强度较高/较弱"这类取舍/自评。取舍的**结果**入正文，取舍的**过程**入台账/脚注。
4. **无结构暴露**：不用"本节/下一小节/如前文/详见第 X 章"把文档骨架讲给读者；关联通过内容衔接实现（见 `stage-7-writing.md` §7.0"卡片关系字段→叙事衔接"）。
5. **限定词克制**：不确定性标注（据称/尚未证实）用于**具体事实**，一次到位；不把方法论层面的自我怀疑反复铺陈成段。
