# 红队审查详细清单

## 审查原则

红队审查的目标不是"挑刺"，而是**防止报告在关键论证上塌方**。
审查者应假设自己是报告的反对者，试图找出最薄弱的环节。

---

## 一、证据链审查

逐章检查：

- [ ] 每个关键判断是否都有至少一个 A/B 级来源支撑？
- [ ] 哪些段落只有 C/D 级来源甚至无来源？
- [ ] C/D 级来源的事实是否标注了强度（如"据称""尚未独立证实"）？
- [ ] 引用的来源是否真实存在且可访问？
- [ ] 数字、日期、人名是否与原始来源一致（抽查至少 5 处）？

**重点关注**：
- 全段无来源标注的"流畅叙述"——往往是写作者自己推断的
- 脚注/引用与正文事实不匹配的情况
- 同一来源在不同章节被引用但表述不一致

---

## 二、逻辑链审查

逐章检查：

- [ ] 从 A 推出 B 的中间环节是否缺失？
- [ ] "因此""显然""必然""无疑"之前的论证是否真的充分？
- [ ] 是否存在"相关即因果"的谬误？
- [ ] 是否存在"个例推广为规律"的谬误？
- [ ] 结论的强度是否与证据的强度匹配？

**重点关注**：
- `A 发生了，B 也发生了 → A 导致 B`（可能只是时间先后）
- `X 公司/国家做了 Y → Y 是趋势/必然`（可能只是个案）
- `没有证据否定 X → X 成立`（诉诸无知）

---

## 三、夸大表述审查

全文搜索以下词汇，检查是否有 A/B 级证据支撑：

| 词汇类型 | 关键词 | 无 A/B 级证据时处理 |
|---|---|---|
| 首次性 | "首次""第一个""首个""开创" | 删除或改为"据称""较早之一" |
| 程度 | "完全""全部""彻底""根本" | 改为"部分""主要""在很大程度上" |
| 速度 | "秒级""瞬时""实时" | 改为"显著缩短""亚分钟级"等有证据的说法 |
| 决定性 | "决定性""根本性""颠覆" | 改为"重要""显著""关键"并加限定条件 |
| 唯一性 | "唯一""独有""无可替代" | 改为"主要""核心""少数几个之一" |

---

## 四、概念堆砌审查

逐段检查：

- [ ] 哪些段落只有名词列表而无机制解释？
- [ ] 哪些概念之间的关系没说清楚？
- [ ] 哪些术语在该领域有特定含义但被当作通用词汇使用？
- [ ] 是否存在"用更难懂的词解释难懂的词"的情况？

**测试方法**：遮住段落中的术语，看剩下的句子是否还有实质内容。

---

## 五、偏题审查

逐章检查：

- [ ] 这章内容是否直接回答核心问题？
- [ ] 哪些部分是"背景科普"而非"分析"？
- [ ] 哪些案例与核心论点无关？
- [ ] 篇幅分配是否与章节重要性匹配？

---

## 六、一致性审查

跨章检查：

- [ ] 同一事实在不同章节的表述是否一致？
- [ ] 同一术语在全文中是否统一？
- [ ] 不同章节的结论是否矛盾？
- [ ] 案例的结论与总体结论是否一致？

---

## 七、文档结构合规性审查

逐分章文件 + 合并后终稿检查：

- [ ] 每个分章文件是否存在与 `outline.md` 章级条目一一对应的 H2 章容器标题（`## 第N章 标题`）？是否存在只写到 H3"节标题"、遗漏 H2 章容器的情况（详见 `references/writing-process-pitfalls.md` 问题1）？
- [ ] H3/H4 标题是否都正确嵌套在某个 H2/H3 之下，有无跳级（如 H2 之后直接出现 H4，中间缺 H3）？
- [ ] 标题文字本身是否混入了手动编号（如"1. 导论""1.1 背景"）？编号应完全交给阶段9转换脚本自动生成，正文标题只写纯文字（详见 `stage-7-writing.md` §7.2.2）
- [ ] 是否存在多个 H1（除全文唯一的前言/导论主标题外）？分章文件中出现 H1 会在合并后产生多主标题冲突
- [ ] 图/表引用是否均使用具体编号（"图 3-2""表 3-2"），有无"上表""下图""如上所述的表格"这类位置性指代残留（详见 `writing-standards.md` 标准6）？

**重点关注**：
- 分章写作 Agent 逐字仿照规范文档的示例，把示例中的层级结构照抄错——例如把"章容器"示例误当作"节标题"的唯一格式，导致全篇缺少章级容器标题
- 合并后标题编号呈现扁平的"0.1～0.57"格式而非"第一章/1.1/1.1.2"层级格式，是本项检查要捕获的典型故障信号

---

## 八、文风终审（可选，捕获工作流中间数据/示例格式残留）

逐分章文件 + 合并后终稿检查，排查两组"看起来像正文但实际不该入正文"的问题。

**A 组·协作过程/示例格式残留**（根源：规范文档/契约模板中的示例格式被写作 Agent 机械字面复制）：

- [ ] **写作者自声明残留**：正文中是否出现`### 写作者自声明（第 X 章）`标题及其下方内容（字数/图数/表数/card_id 列表）？这是 `chapter_writer_agent` 契约产出的审计中间数据，绝不应出现在最终交付文档中（详见 `agents/chapter_writer_agent.md`）
- [ ] **字面三段标签残留**：正文中是否出现`**主张**：……**证据**：……**推理**：……`这类字面加粗标签？"主张→证据→推理"是组织顺序原则，不是格式模板，正文应为连贯叙述（详见 `writing-standards.md` 标准8）
- [ ] **跨章自我指涉**：正文是否出现"如前文所述本章将……""本节承接上一小节的自声明"这类暴露写作过程本身、而非论证内容的表述？
- [ ] **位置性指代残留**：是否仍存在"上表""下图""如上所述"这类依赖排版位置的指代（详见本文件"三、夸大表述审查"上方"七、文档结构合规性审查"最后一项，及 `writing-standards.md` 标准6）？

**B 组·后台过程外泄**（根源：把编辑部的核验/分级/取舍/结构编排当作正文叙事对象——`writing-standards.md` 标准0"前台/后台分离"要拦截的核心失效）：

- [ ] **后台过程外泄残留**：正文是否出现"A 级/B 级/C 级来源""证据强度较高/较弱""本报告采用……不采用……""尚未见独立信源证实""本次核验范围内"这类**编辑部核验/取舍过程**被当作正文叙事对象？这类内容应为脚注/来源标注或删除（详见 `writing-standards.md` 标准0、`stage-7-writing.md` §7.0 铁律4）
- [ ] **claim_id / 台账编号残留**：正则搜索 `\[[A-Z]{1,3}\d{3}\]`（如 `[CM021]` `[CO012]`）——台账主键绝不应出现在正文，读者看到的是上标编号 + 文末 GB/T 7714 参考文献列表
- [ ] **参考文献信源分级残留**：参考文献列表中是否出现 `[A]`/`[B]`/`[C]`/`[D]` 前缀（正则 `^\s*\[[ABCD]\]`）？信源分级属于内部质量控制，不应出现在读者可见的参考文献中（见 `研究报告格式规范.md` §8.2、`writing-standards.md` 标准 0）
- [ ] **结构暴露（坐标指路超限）**：搜索"见第.{0,6}章""详见第.{0,6}节""与第.{0,6}节呼应""如前文限定"等纯坐标指路——是否超出本报告类型的前向引用限额（brief=0 / research・policy≤3 / proposal・tech-eval≤6，见 `stage-7-writing.md` §7.2"前向引用坐标指路的分类型限额"）？坐标指路应改为内容衔接

**重点关注**：A 组问题共同根源是"规范文档/契约模板中的示例格式被机械字面复制"（对照 `references/writing-process-pitfalls.md` 问题2/2b、问题3）；B 组问题共同根源是"研究笔记/证据台账是后台、报告正文是前台，写作 Agent 把后台过程翻译进了前台"（对照 `writing-standards.md` 标准0）。两组都不是内容质量问题本身，而是"哪些内容不该出现在成品正文里"的问题。

### 风险处理标准

- **高风险**：可能导致报告核心结论被推翻 → 必须处理
- **中风险**：影响局部论证可信度 → 至少 80% 处理
- **低风险**：措辞可优化但不影响实质 → 酌情处理
