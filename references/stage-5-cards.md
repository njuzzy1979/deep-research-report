# 阶段 5：专题研究——卡片与证据包

> 本文件是 deep-research-report skill 的阶段 5 详细 spec，从 SKILL.md 拆分而来。
> 母文件：`../SKILL.md`（流程索引）

---

卡片是**事实核验台账（阶段 3）和正文写作（阶段 7）之间的中间产物**：台账里是零散的、逐条的事实主张，写作时需要的是"一个案例/一项技术/一套架构/一个概念"的完整叙事单元。卡片把台账中相关的主张组织成结构化单元，同时不丢失每条判断背后的证据链。

> **⚠ 卡片的定位：写作前的"思维脚手架 + 事实锚点"，不是可直接拼接的正文草稿。** 卡片离正文**不是只差一步翻译**——若把卡片当成"照字段翻译即成正文"，写作就退化为逐卡誊抄（这正是本 skill 曾出现的写作失效根因）。正确用法是：卡片的"叙事化判断"字段（见 §5.3）供写作者消化为论点，其余字段供写作时查证事实；正文从**论点骨架**出发、回填卡片事实（见 `stage-7-writing.md` §7.3），而非顺着卡片字段逐条铺陈。

## 5.0 卡片文件存放约定

本 skill 使用四类卡片，对应四个固定子目录（位于 `research/notes/` 下）。目录名是固定契约——`stage-1-init.md` §1.2 按此创建，`card_synthesizer_agent` 按此产出，`card_overlap_check.py` 的调用方按此传入 `--cards` 参数。若需改名，只改此处和 `stage-1-init.md` §1.2，不可在各 Agent prompt 中单独修改。

| 卡片类型 | 目录名 | card_type 值 | card_id 前缀 |
|---------|--------|-------------|-------------|
| 案例卡 | `case-cards/` | 案例卡 | CASE- |
| 技术/主题卡 | `tech-cards/` | 技术卡 | TECH- |
| 架构卡 | `architecture-cards/` | 架构卡 | ARCH- |
| 理论/概念卡 | `theory-cards/` | 理论卡 | THEORY- |

> **架构卡不参与卡片-正文重合度检测**：架构卡的下游是阶段 6 出图而非正文叙事，因此 `card_overlap_check.py` 调用时不传入 `architecture-cards/` 目录。

## 5.1 卡片类型与下游用途

每类卡片对应下游一个明确的使用环节，不是产出后自由存放：

| 卡片类型 | 内容 | 下游用途 |
|---|---|---|
| **案例卡** | 一句话论点、名称、时间线、问题、动作、技术支撑、效果、证据包、风险争议、可提炼机制 | 直接填充 4.2 可选模块中的"案例分析"章节（命中案例研究法时）；每张卡对应案例分析章节的一节 |
| **技术/主题卡** | 机制小结、核心概念、架构位置、输入输出、关键数据、证据包、与其他组件关系、局限 | 支撑核心分析章节的机制阐述——写作时以"机制小结"为消化后的论点锚点，"输入输出/关键数据/局限"作事实库供查证，不逐条誊抄为正文 |
| **架构卡** | 架构名称、所属层次、组件与关系、数据流、证据包、验证方式、对应的图表 | **阶段 6 出图的直接依据**——"组件与关系""数据流"是绘制架构图的素材来源，不是阶段 4.3 图表清单能替代的细节 |
| **理论/概念卡** | 采用定义、概念定义、提出者/来源、证据包、应用场景、与其他概念关系、争议 | 支撑前言/导论的概念界定部分，及核心分析中对理论框架的引用 |

## 5.2 证据包——卡片与事实核验台账的绑定方式

**证据包**：卡片中每条关键判断对应的最小引用单元 = `claim_id`（指向 `claims-ledger.csv` 的核验记录）+ 该记录的 `evidence_sources`（指向 `source-index.csv` 的来源）。

不用笼统的"证据等级：中"这样一个印象分描述整张卡片——卡片里通常有 3-5 条不同强度的判断（例如案例卡的"效果"是强判断需要 A/B 级证据，"风险与争议"可能只有 C 级来源），**每条关键判断单独标注证据包**，卡片整体的可信度是这些证据包的最低值，不是平均值或主观估计。

## 5.3 卡片模板（四类，均含证据包字段）

> **叙事化判断字段（案例卡/技术卡/理论卡各一个必填字段，置于卡片最前）**：这是卡片的"消化层"——用你自己的话写的**连贯句子**（对标 Zettelkasten 的 literature note），是写作时可直接消化使用的**成品判断锚点**。其余字段（时间线、数字、证据包等）是"锚点/事实库"，供写作时**查证**而非照抄。
> **⚠ 关键约束**：叙事化判断字段是**思考锚点，供写作者展开成段落，不是段落本身**——写作时这句判断会被拆解、扩写、与其他卡片的判断编织进论证，**不应原句照抄进正文首句**（原句照抄会被阶段 7 审计的"卡片-正文重合度"维度命中，见 `agents/chapter_auditor_agent.md`）。架构卡不加此字段，因其下游是"出图"而非"正文叙事"，字段化是恰当的。

案例卡：
```markdown
## 案例名称
0. **一句话论点**：本案例用于支撑的核心判断是什么（一个完整句子，读者视角，不含字段标签、不含证据包编号）——必填
1. **时间线**：
2. **背景问题**：证据包 [claim_id]
3. **关键动作/适变**：证据包 [claim_id]
4. **技术/业务支撑**：证据包 [claim_id]
5. **效果（量化优先）**：证据包 [claim_id]
6. **风险与争议**：证据包 [claim_id]
7. **可提炼机制**：
```

技术/主题卡：
```markdown
## 技术/主题名称
0. **机制小结**：把"输入输出/关键数据/局限"三个点合起来，用 2-3 句连贯的话说明这项技术"做什么、靠什么做到、边界在哪"（连贯句子，非要点罗列）——必填
1. **核心概念**：
2. **架构位置**：（在阶段 1.3 分析框架中所属的层次）
3. **输入输出**：证据包 [claim_id]
4. **关键数据**：证据包 [claim_id]
5. **与其他组件关系**：
6. **局限**：证据包 [claim_id]
```

架构卡：
```markdown
## 架构名称
1. **所属层次**：（对应阶段 1.3 分析框架的哪一层）
2. **组件与关系**：（用于阶段 6 出图的核心素材）
3. **数据流**：证据包 [claim_id]
4. **验证方式**：（该架构判断如何被核实，如官方文档/逆向分析/访谈）
5. **对应的图表**：（图号，阶段 6 出图时回填）
```

理论/概念卡：
```markdown
## 概念名称
0. **采用定义（正文用）**：一句话给出本报告将采用的该概念定义（把"争议/证据脆弱性"留在下方"争议"字段做后台，不写进这句）——必填
1. **定义**：证据包 [claim_id]
2. **提出者/来源**：
3. **应用场景**：
4. **与其他概念关系**：
5. **争议**：证据包 [claim_id]
```

## 5.4 卡片索引登记——让"卡片有没有被用上"可追溯

每张卡片产出后，登记到 `research/notes/card-index.csv`（模板见 [`references/card-index-template.csv`](card-index-template.csv)），字段：

`card_id, card_type, title, chapter_ref, evidence_packet_refs, credibility_summary, status, used_in_chapter, transcription_check`

- `card_id`：卡片唯一编号（如 CASE-01、ARCH-02）
- `chapter_ref`：对应大纲中的章节号（写卡片时填，来自阶段 4 大纲）
- `evidence_packet_refs`：该卡片关联的 claim_id 列表（分号分隔）
- `status`：draft / final
- `used_in_chapter`：**阶段 7 写作时回填**——写完一章后，将该章实际引用过的卡片 ID 标记对应章节号；未使用则留空
- `transcription_check`：**阶段 7 审计时回填**——审计 Agent 跑完"卡片-正文重合度"检测（见 `agents/chapter_auditor_agent.md`）后写入该卡片的转写状态：`pass`（无异常重合）/ `overlap-flagged`（触发 OVERLAP-HIT，正文疑似誊抄卡片判断句，已回炉）/ `waived-facts`（存在长重合但经判读为专有事实豁免，非誊抄）。供阶段 8 红队和阶段 9 定稿复核哪些章曾触发重合告警

**先登记再写作**。卡片不登记直接拿去写，等于放弃了阶段 8 检查"哪些调研成果被浪费"的能力。

### ▶ 阶段 5 质量门槛

- [ ] 每个核心章节至少有 3 张专题卡片
- [ ] 每张案例卡/技术卡/理论卡均已填写必填的叙事化判断字段（案例卡"一句话论点"/技术卡"机制小结"/理论卡"采用定义"），且为读者视角的连贯句子，不含字段标签/证据包编号（架构卡不要求）
- [ ] 每张卡片的关键判断均标注了证据包（claim_id），不是笼统的单一证据等级
- [ ] 卡片之间无矛盾（如有矛盾已在卡片中标注）
- [ ] 所有卡片已登记到 `card-index.csv`，`chapter_ref` 字段完整
