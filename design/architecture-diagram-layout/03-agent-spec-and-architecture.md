## 1. 核心论证：为什么不能只加自然语言规范

### 1.1 通行的二分法是错的

该 skill 内部流行一个判断——"自然语言约束效力接近零，必须配机器门禁"。`architecture_chart_agent.md:54` 自己就写着：

> 上面 5 条是自然语言约定，**无一可机器校验**——这是"出图规范存在但从不生效"的直接来源。

**但这个二分法不准确。** 反例就在同一份文件里：DPI 那条也是自然语言，却**生效了**，因为配了 `figure_gate.py`。

真正的规律是：**有检查器则有效。**

### 1.2 但对布局而言，光配检查器仍然不够

关键区别在**修复算子**：

| 检查项 | 失败后的修复算子 | 性质 |
|--------|-----------------|------|
| DPI 不足 | `img.save(dpi=300)` | **确定性、一步收敛** |
| 宽度不足 | 提高导出 scale | **确定性** |
| **节点重叠** | **"LLM 重算坐标"** | **本身就是缺陷源** |

**3-1 的 `x="None"` 是这个算子失效的物证**：Python 的 `None` 被 `str()` 写进了 XML —— 说明当时确实有代码/模型在算坐标，且算出 None 时无人校验。

**给一个缺陷算子配更严的检查器，只会得到不收敛的重试循环，其出口必然是降级绕过。**

### 1.3 最强的本项目实证（E9）

`architecture_chart_agent.md` **已经**明文写了"必须跑 figure_gate""exit code 非零即不得交付"，`figure_gate.py` 也**确实有效**（实跑 exit=1 拦住了 3-1）——**缺陷图仍然交付了**。

这说明：**在 Agent 定义里写"你必须跑某脚本"，效力同样接近零**，因为没有任何机制验证它真跑了、以及退出码真被尊重。

**结论：D5 的主体交付不是"再加 10 条布局规范"，而是替换修复算子——语义与算术分离。**

## 3. 组件分解与数据流

```
┌─────────────────────┐
│ architecture_chart_ │  只输出语义，零坐标
│      agent          │
└──────────┬──────────┘
           │ figure-ir.json      ← additionalProperties:false 禁止坐标字段
           ▼
┌─────────────────────┐
│  drawio_generator   │  确定性坐标计算（五种模式 + snap + bbox 反推）
│       .py           │  写入 provenance 标记
└──────────┬──────────┘
           │ *.drawio（明文 mxGraphModel）
           ▼
┌─────────────────────┐
│ drawio_layout_      │  【门禁 1】源文件层几何校验（零依赖）
│   validator.py      │  → .layout-gate-report.json
└──────────┬──────────┘
           │ exit 0 才继续
           ▼
      导出 PNG
           │
           ▼
┌─────────────────────┐
│   figure_gate.py    │  【门禁 2】产物层（存在性/宽度/DPI）—— 复用现有
└──────────┬──────────┘
           │ exit 0
           ▼
      交接阶段 7
```

**失败回退**：门禁 1 失败 → 按失败路由表分类 → Agent 修改 **IR**（非坐标）→ 重新生成 → 重跑。

**为何门禁 1 必须先行**：PNG 层诊断具**误导性**。3-1 在 figure_gate 报"宽度 325px 不足"，Agent 若照此去加大导出 scale，只会得到 650px 的同样残缺的图。**真因只在源文件层可见。**

## 4. IR（中间表示）设计

### 4.1 设计原则

**Agent 声明"是什么"和"怎么排"，脚本决定"在哪里"。**

```jsonc
{
  "figure_no": "8-1",
  "title": "SCOS 十四层总体架构",
  "layout_mode": "stack",        // stack|pyramid|flow|star|grid|quadrant|manual
  "layout_params": { "cols": 2 },
  "nodes": [
    {
      "id": "L1",
      "label": "物理感知层",
      "group": "infrastructure",   // 语义分组 → 决定配色
      "rank": 1,                   // 层次序 → 决定堆叠顺序
      "emphasis": false
    }
  ],
  "edges": [ { "from": "L1", "to": "L2", "label": "", "style": "orthogonal" } ]
}
```

### 4.2 关键约束（**D5-13 已订正承诺范围**）

- **JSON Schema 设 `additionalProperties: false`**，且节点对象**不含** `x`/`y`/`width`/`height` 字段。
- `rank`/`group` 是**语义**（Agent 的职责），坐标是**算术**（脚本的职责）。

> ⚠️ **D5-13 订正（第二轮审查 C-C2）**：D5-R1 原宣称"**3-1 类故障在输入端不可表达**"。**该承诺是错的** —— `layout_mode: manual` 分支**允许 Agent 写坐标**，故 manual 图完全可以再次产出 `x="None"`。**核心承诺在自己的逃生舱上失效。**
>
> **三选一处置（06 号 §3.2 列出），本方案选定第 2 项**：
>
> | 选项 | 内容 | 取舍 |
> |------|------|------|
> | 1 | manual 也不许写坐标（改用确定性重排） | 与 §12 中间方案重合，属另一条路线，本批次不选 |
> | **2** | **降级承诺范围** | ✅ **选定** |
> | 3 | 取消 manual | 会造成模式覆盖不足时无出路（G10a 实测 3/15 需 manual） |
>
> **订正后的承诺（严格表述）**：
>
> > 对 `layout_mode ≠ manual` 的图，几何字面值错误（3-1 类）在 IR 输入端**不可表达**。
> > 对 `layout_mode == manual` 的图，该承诺**不成立** —— manual 图的几何完整性**由 G1 校验兜底**，而非由 schema 保证。
>
> **补偿措施**：manual 图的 G1 判据**不可豁免**（02 号 §6.2 已规定豁免仅对 G2 开放），且 manual 图仍走常规校验（02 号 §6.3）。**即：manual 放宽的是布局模式纪律，几何质量一律不放宽。**

### 4.2.1 manual 模式的强制字段（C-2 修订）

`layout_mode: manual` 不再是无成本的逃生舱：

```jsonc
{
  "layout_mode": "manual",
  "manual_reason": "主链 s1→s2→s3 后分出 3 条预测分支并汇合至 Decision，属混合拓扑",
  "attempted_modes": [
    { "mode": "flow", "failed_with": "FLOW_RECONVERGENT: s3 出度=3 分叉，s4 入度=3 汇合" },
    { "mode": "grid", "failed_with": "GRID_HAS_CONNECTED_STRUCTURE: 最大连通块 9/12" }
  ]
}
```

| 约束 | 判据 |
|------|------|
| `manual_reason` 非空 | 空 → `MANUAL_UNJUSTIFIED` **error** |
| `attempted_modes` 非空且**实际尝试过** | 生成器须真跑过所列模式并记录失败原因；未尝试 → `MANUAL_UNJUSTIFIED` **error** |
| manual 占比即时门禁 | 单次运行内 **> 40% → exit 非零**（**不再采用**"连续 2 个项目"的滞后统计） |

> **为何改为即时门禁**：审查正确指出，滞后统计意味着"前两个项目已经烂掉了才发现"。
- `layout_mode: manual` 是逃生舱：允许坐标，但**强制 strict 校验 + 重试预算 0 + 报告中登记**。

### 4.3 语义表达力的损失（诚实标注）

Agent 无法表达模式之外的布局意图。实测 15 张中 4-2（主链+分支+汇合）属混合拓扑，模式覆盖不了 → 至少 1/15 需走 manual。**真实项目的 manual 比例未知**，需 B1 上线后统计。

### 5.2 自检节改写（替换现有 §自检 第 52-63 行）

```markdown
### 自检：两级门禁，源文件层先行

**门禁 1 —— 几何校验（新增，必须先跑）**：

    python scripts/drawio_layout_validator.py --figures-dir research/figures

**门禁 2 —— 产物校验（现有）**：

    python scripts/figure_gate.py --outline research/outline.md \
        --figures-dir research/figures --stage stage6

**退出码必须被检查，禁止吞码。** 以下写法会使门禁失效：

    # ❌ 错误：取到的是 tail 的退出码，永远是 0
    python scripts/figure_gate.py ... | tail -40; echo $?

    # ❌ 错误（PowerShell）：$? 是布尔，不是原生 exe 的退出码
    python scripts/figure_gate.py ...; if ($?) { "通过" }

    # ✅ 正确（bash）
    python scripts/figure_gate.py ...
    if [ $? -ne 0 ]; then echo "门禁失败，不得交付"; exit 1; fi

    # ✅ 正确（PowerShell，本项目 Windows 环境）
    python scripts/figure_gate.py ...
    if ($LASTEXITCODE -ne 0) { throw "门禁失败，不得交付" }
```

> `$?` vs `$LASTEXITCODE` 是本项目 Windows 中文环境的**特有陷阱**：PowerShell 中 `$?` 是布尔量，取原生 exe 的整数退出码必须用 `$LASTEXITCODE`。

### 5.3 失败路由表（新增节）

| error_code | 含义 | 处置 | 是否重试 |
|-----------|------|------|---------|
| `GEOMETRY_INVALID` | 几何字面值非数值 | **生成器 bug，直接上报** | **否** |
| `HARD_OVERLAP` | ink-box 硬重叠 | 调 density → 换 pattern → 拆图 | 是 |
| `CONTENT_OVERFLOW` | 内容跨度 > 1.8× page | 换模式或拆图 | 是 |
| `NODE_LIMIT_EXCEEDED` | 节点数超模式上限 | 拆图或换模式 | 是 |
| `EMBEDDED_CAPTION` | 画布内嵌图注 | **移文本到 Markdown 后重跑** | **否** |

## 8. warn → blocking 切换条件（**D5-15 已解开死锁**）

> ⚠️ **原设计有两处缺陷**（第二轮审查 C-C5）：
> 1. 用"**连续 2 个项目**"滞后统计，与 00 号 §9.2 明确的"**不再采用滞后统计**"（理由：前两个项目已经烂掉才发现）**原则冲突**；
> 2. 切换条件依赖 B4/B5 产物（"100% 经生成器产出"）—— **若 B4/B5 按放弃条件被放弃，校验器将永久停在 warn 模式，门禁永不生效 = 死锁**。

**第三轮定案：切换条件仅依赖零参数判据，与 B4/B5 完全解耦。**

| # | 条件 | 数据来源 | 为何零参数 |
|---|------|---------|-----------|
| 1 | `summary.vertex_geometry_broken == 0` | G1 | 纯 XML 语义合法性，无阈值 |
| 2 | G6 内嵌图注命中数 == 0 | G6 | 纯正则匹配，无阈值 |
| 3 | 无 `retryable=false` 类 error | G1/G6/G10a | 同上 |
| 4 | **连续 2 次运行**满足 1-3 | — | 见下方说明 |

**与 B4/B5 的关系：无。** 上述四条全部可在 **B1（仅零参数判据）** 阶段测得，**B4/B5 是否执行不影响切换**。死锁消除。

> **关于"连续 2 次运行"与"不采用滞后统计"是否冲突** —— 不冲突，二者是不同性质的判定：
>
> | 机制 | 性质 | 频率 |
> |------|------|------|
> | `manual_ratio > 40%` | **即时门禁**（每次运行判定通过/失败） | 每次 |
> | warn→blocking | **一次性配置切换决策** | 一生一次 |
>
> 即时门禁不能滞后（否则坏图已交付）；而"是否把门禁从观察模式切到阻断模式"是**运维决策**，需要少量历史样本证明不会大面积误伤 —— 这是审慎，不是滞后。**原设计的问题不是"用了 2 次运行"，而是"依赖 B4/B5 产物"。**

**且切换不再需要人工判断**：四条均为机器可判定，可由校验器自身输出 `switch_eligible: true/false` 字段，避免"待评估后再切"这类无人跟进的承诺。
