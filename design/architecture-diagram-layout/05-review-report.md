### 1.1 A-C1【Critical】G10「修正后」的代码实际会放行 4-2 —— 已复现确认

```

判据 `if max_out > FLOW_MAX_FANOUT` => 3 > 3 => False
```

**指控成立。** 01 号 §3.7.2 表格中 4-2 标注的"⚠️ 边界（=3）"、00 号 §9.1 的"4-2 被标记"、07 号附录 L 的同类叙述，**三处全部与代码实际行为相反**。

### 1.2 A-C2【Critical】G10 两个阈值系后验凑数 —— 已复现确认

**编排器阈值敏感性实测**：

```
FLOW_MAX_FANOUT=2 -> flow 类被标记: ['4-2']
FLOW_MAX_FANOUT=3 -> flow 类被标记: 无
FLOW_MAX_FANOUT=4 -> flow 类被标记: 无

```

**唯一能拦住 4-2 的取值是 2，但那会同时拦住 8-2（max_out=2）** —— 即：**不存在任何一个 `FLOW_MAX_FANOUT` 取值能同时正确处理 4-2 与 8-2**。该阈值在此样本上**根本无法完成判别任务**。

```
10-1=0.000  11-1=0.000  6-1=0.091  5-1=0.143  7-1=0.688
```

0.5 落在 0.143 与 0.688 之间的**空白区**，是任意取的中点，无数据依据。

**指控成立。**

## 2. 第二轮审查：分支 B（接口与流程可执行性）

### 2.1 B-C1【Critical】manual 逃生舱的「第二层死锁」

编排器在本轮已解开第一层死锁（`forced` / `elective` 分类计数）。**但审查 B 发现第二层**：

即使 manual 占比不超 40%，manual 图仍被规定**强制走 `--strict` 模式**（02 号）且**重试预算 = 0**（03 号）。而 `--strict` 会把 warning 一并计入失败——实测现有 15 张图共 12 个 warning，**strict 下全部转红**。

**后果**：任何进入 manual 的图，都会因 strict 而失败，且重试预算为 0 → **无出路**。这是比第一层更隐蔽的死锁。

### 2.2 B-C2【High】exit code 五档在实际调用下退化为两档

调用方（含 D5 自己在 04 号写的示例）一律写 `if ($LASTEXITCODE -ne 0)`，故 exit 2/3/4 **全部退化为"失败"**。

**且同仓库已有正确范式未被采纳**：`figure_gate.py:436-462` 的做法是**条件性判断**——只有当 `declared > 0` 且清单为空时才判 FAIL，否则返回 `passed: True`。D5 应直接复用该范式，而非发明 exit 4 再另配跳过机制。

### 2.3 B-C3【Medium】02 号的事实错误：测试目录

02 号 §8 称"仓库唯一测试目录为 `scripts/md2docx/tests/`"——**事实错误**。顶层 `tests/` 存在，且被 `selfcheck.py:45-48` 的 `_TEST_SUITES` 覆盖（`("tests", "tests")`）。新测试应放顶层 `tests/`。

## 3. 第二轮审查：分支 C（体系定位与投入产出）

### 3.1 C-C1【Critical】D5-R1 核心裁决的物证归因错误

**D5 最核心的裁决**（语义/算术分离、Agent 只出 IR）建立在一条论证上：3-1 的 `x="None"` 证明"LLM 算坐标不可靠"。

**审查 C 指出该归因错误**：`"None"` 是 **Python `str(None)` 的痕迹**——是**脚本 bug**（某段代码把 `None` 变量格式化进了 XML），而非 LLM 的算术失误。LLM 生成文本时不会产出 `x="None"` 这种字面量。

**影响**：物证归因错误 → "必须用 IR 才能解决"的论证**站不住**。正确的修复是 **G1 输出校验**（生成时校验几何值是否为合法数值），**不需要 IR**。

这直接动摇 B4/B5（最高成本批次）的价值主张。

### 3.2 C-C2【Critical】manual 分支与 D5-R1 的承诺直接矛盾

D5-R1 宣称"IR schema 设 `additionalProperties: false`，**3-1 类故障在输入端不可表达**"。但 `layout_mode: manual` 分支**允许 Agent 写坐标** → manual 图完全可以再次产出 `x="None"`。

**核心承诺在自己的逃生舱上失效。** 需三选一：
1. manual 也不许写坐标（改用确定性重排）；
2. 降级承诺范围（改为"非 manual 图不可表达"）；
3. 取消 manual。

### 3.3 C-C3【Critical】G10 并不依赖 IR，"必须等 B4"是包装

编排器在本轮把 C-1 降级为"判据已设计但 B4 前不生效"，理由是 G10 依赖 IR 字段。

**审查 C 指出这个理由不成立**：D5 自己验证 G10 用的**全部实测数据都是从现有 `.drawio` 算出来的**（边集、出入度、hub 度数均可直接解析）。只有 `stack` 分支的 `rank` 需要声明。

**正解：拆分为两个判据**
- **G10a**（拓扑自洽性）：`flow`/`star`/`grid` 分支，纯边集判定，**B1 即可生效**；
- **G10b**（模式声明一致性）：`stack` 的 rank 校验，需 IR，**B4 后生效**。

"必须等 B4"是**实施顺序选择被包装成了技术必然性**。

### 3.4 C-C4【High】00 号三处对 02/04 落盘状态给出矛盾答案

00 号 §1 索引、§9.6、§11 对 02/04 号是否已落盘的表述**互相矛盾**（§9.6 仍写"02/04 未落盘"，而 §1 已标"已落盘"）。而 **C-1 的降级证据恰好引用这两份文档** → 证据链指向状态不明的文件。

### 3.5 C-C5【High】03 号 §8 与 00 号 §9.2 的原则矛盾 + 切换死锁

- 03 号 §8 的 warn→blocking 切换门槛用"**连续 2 个项目**"滞后统计，而 00 号 §9.2 明确"**不再采用**滞后统计"（因为"前两个项目已经烂掉才发现"）。**两处原则冲突。**
- 更严重：03 号 §8 的切换条件依赖 B4/B5 的产物（100% 经生成器产出）。**若 B4/B5 按放弃条件被放弃，校验器将永久停在 warn 模式** → 门禁永不生效 → 死锁。

### 3.6 C-C6【High】53.3% 属循环论证，应改走零参数路径

53.3% 是用 **D5 自己的判据**（含 `INK_INFLATE`、`MIN_INK_THICKNESS` 两个未验证的拟合参数）算出的。若判据偏严，合格率被压低，从而"证明"B4/B5 必要 —— **用自己的判据证明自己的必要性**。

且 7 张 FAIL 图中 **6 张仅因 G2 重叠而 FAIL**，G2 恰恰是拟合参数所在。

**编排器已按审查意见补算零参数口径**：

| 口径 | 判据 | 合格率 | 依赖拟合参数 |
|------|------|-------:|:---:|
| 原口径 | G1+G2+G3+G6+G7 | 53.3%（8/15） | ✅ 是 |
| **零参数口径** | **G1+G6** | **73.3%（11/15）** | ❌ **否** |

**73.3% 是不可反驳的下限**——纯由"XML 语义是否损坏""是否有图注 mxCell"决定，无任何拟合值。

> **注意：73.3% 仍低于 85% 放弃阈值**，故 B4/B5 未被否决的结论**在零参数口径下依然成立**，但论证强度显著减弱（差距从 31.7 个百分点缩至 11.7 个）。**论证路径应改走 G1+G6，放弃 53.3%。**

### 3.7 C-C7【High】中间方案「确定性重排」未被评估

审查 C 提出：**Agent 仍写坐标，校验失败时用确定性脚本重排后重跑校验，不引入 IR**。

该方案的关键优势：
- 保留 Agent 的完整语义表达力（无 IR 枚举限制）；
- 修复算子仍是确定性的（解决 D5-R1 真正想解决的问题）；
- 成本远低于 B4/B5 全 IR 重构；
- **不产生 manual 逃生舱**（无 IR 即无 `layout_mode` 概念）→ C-C2 矛盾自动消失。

**D5 跳过了这个更轻量的选项，直接选了最重的重构。** 必须在 06 号做正面对比。

## 6. 方法论教训（本方案最有价值的产出之一）

D5 在同一个项目内**三次**犯下同一类错误：

| 次序 | 错误 | 发现者 |
|------|------|--------|
| 1 | 沿用问题记录的失真数字（362 个重叠等）作为设计依据 | 发现层实测 |
| 2 | G10 初版误伤 73% 正常图；ink-box 初版假阴性 67% | 编排器自查 |
| 3 | **G10「修正版」在唯一样本上不触发；三处文档叙述与代码相反** | **第二轮独立审查** |

**共同模式：结论先于验证被写入文档。**

第 3 次尤其值得记录——它发生在编排器**已经因为同类错误自我批评过一次之后**，且发生在编排器**自认为已经"用实测拦下缺陷"的那次修正里**。这说明：

> **自我复核无法替代独立审查。** 编排器在做"修正"时，验证的是"修正后指标是否变好"（11/15 → 1~2/15），而非"修正后的代码逻辑是否正确"。指标变好恰恰掩盖了 `3 > 3 == False` 这个基础错误。

这与 D5 自己在 M-8/M-11 警示的"过拟合/自我验证"风险**完全同构**——协调者要求"不要自己既当设计者又当审查者签字通过"的判断是正确的，且被本轮结果直接证实。
