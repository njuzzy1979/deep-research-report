### 3.1 E9 的意义（决定了 D5 的重心）

`figure_gate.py` 有效、`architecture_chart_agent.md` 也已明文要求"必须跑 figure_gate、exit code 非零即不得交付"——**规范存在、脚本有效，缺陷图仍然交付了**。

失效路径收窄为两条：
- (a) 门禁**从未被实际执行**（Agent 声称跑了但没跑）；
- (b) 门禁跑了，但**非零退出码被吞掉**。

(b) 有强旁证：设计层 agent 自身第一次测量时写了 `cmd | tail -40; echo $?`，取到的是 `tail` 的退出码 0 而非 figure_gate 的 1。该 skill 文档中大量存在 `python xxx.py` 后接管道/重定向的写法。

**结论：D5 的重心不是"补充检查项"，而是"确保检查结果被可靠消费"。** 详见 `04-workflow-integration.md`。

### 3.2 E8 的意义（一种比"没有门禁"更危险的形态）

`references/stage-6-diagrams.md:231` 原文写道：

> **诚实标注**：`fontSize < 12` 与"内嵌题注"两项检查在真实项目上实测 **0 命中**……属"为不存在的问题写代码"，故**不作为阻断依据**。

逐条实测：字号那半**成立**；题注那半**被证伪**。而"0 命中"的真实原因是——**检查器从不解析 `.drawio` 文件**（全仓库 scripts/ 下无任何一行代码解析 mxGeometry）。

这是"用错误的观测面积得出'问题不存在'，再据此主动关掉检查"。与 D1-D4「实测优先」的方法论同源但方向相反：**这次是实测本身做得不够，反而制造了虚假的安全感**。D5 必须更正该断言，并确立一条新规矩：**合并断言必须拆分；任何"0 命中"结论必须附测量口径**。

## 4. 核心设计决策

### D5-R1：语义与算术分离（主体裁决，**第三轮已按 D5-12 削弱**）

**决策**：Agent 只输出**不含任何坐标字段**的结构化清单（IR），由确定性脚本计算坐标并生成 mxCell XML。

> ⚠️ **D5-12 物证归因订正（第二轮审查 C-C1）**：本裁决原以 3-1 的 `x="None"` 作为"LLM 算坐标不可靠"的物证。**该归因是错的。**
>
> `"None"` 是 **Python `str(None)` 的字面痕迹** —— 即某段**脚本代码**把一个值为 `None` 的变量格式化进了 XML 属性。LLM 生成文本时不会产出 `x="None"` 这种 Python 特有的字面量（它会写 `x="0"` 或干脆漏掉属性）。
>
> **这是脚本 bug，不是 LLM 算术失误。**
>
> **对本裁决的影响**：
> 1. 该物证**不再支撑**"必须用 IR"的论证；
> 2. 针对此缺陷的**正确修复是 G1 输出校验**（生成时校验几何值是否为合法数值）—— **不需要 IR**；
> 3. D5-R1 的论证强度**显著下降**：它现在只剩"LLM 手工算坐标在 >20 节点时不可靠"这一**外部证据**（draw.io 官方立场 + GenAI-DrawIO-Creator 论文），**失去了本项目的直接物证**。
>
> **诚实结论**：D5-R1 的方向可能仍然正确，但**其在本方案中的论证基础已不足以支撑 B4/B5 这一最高成本批次**。故 B4/B5 降级为"需与中间方案对比后决策"（见 §12）。

**为什么不能只加自然语言规范**（此论证不受 D5-12 影响，仍然成立）：

通行的"自然语言约束 = 无效"二分法**不准确** —— 同一文件里 DPI 那条也是自然语言，却生效了，因为配了检查器。真正的规律是"有检查器则有效"。

但**修复算子**的差异仍然成立：
- DPI 检查失败 → 修复算子 `img.save(dpi=300)`，**确定性、一步收敛**；
- 重叠检查失败 → 修复算子"LLM 重算坐标"，**不确定、可能不收敛**。

**外部佐证**：draw.io 官方设计立场 + GenAI-DrawIO-Creator 论文实证均支持"LLM 只出拓扑、坐标交给引擎"。量化红线：**节点数 > 20 时，LLM 手算坐标视为禁止项**。

> **但注意**：这个论证只支持"需要确定性的修复算子"，**不唯一指向 IR** —— "确定性重排脚本"（Agent 仍写坐标，失败时脚本重排）同样满足该要求。见 §12 方案对比。

### D5-R2：零第三方依赖（理由已更换）

**决策**：坐标生成器与校验器均采用**纯 Python 标准库**实现。

**理由**（注意：**不是**"因为本机没装"——E10 已证伪该前提）：
1. `PORTABILITY.md` 承诺 `scripts/*.py` 为纯 Python 确定性工具，依赖 shapely/scipy 会击穿他机可移植性；
2. N<200 时朴素 O(N²) 实测 **5.9ms**（编排器）/ 3.25ms（调研复测），引入空间索引属过度工程；
3. 现有 scripts 既有依赖仅 PIL + PyYAML。

**可选增强**：draw.io CLI 原生 ELK 布局（`--layout elkLayered`）是官方更优路径，但需 drawio ≥30.2.5，本机未装 → 写为"若环境具备则优先"的可选项，**不得作为唯一路径**。

**严禁写进方案的库**（经调研证伪不存在）：`pycola`、`pyvpsc`、`adaptagrams`、`pyavoid`、`elkpy`、`pydrawio`。

### D5-R3：重叠零容忍 + ink-box 判据

**决策**：重叠判定**零容忍**，**禁止用 IoU 度量**（分母须为 `min(areaA, areaB)` 而非并集，用 IoU 属概念误用）。依据 Sprawlter（TVCG 2020）明确反对"轻微重叠可容忍"。

**ink-box 判据解决了"面积区间悖论"**：原始难题是有害的 `ql4↔p12`(3042px²) 比无害的 `ql1↔ql2`(3744px²) 面积还小，**单纯面积阈值不可分**。根因是居中文本框的 AABB 含大量空白 padding。按实际文字墨迹收缩后：

| 重叠对 | AABB 面积 | ink-box 面积 | 性质 |
|--------|----------|-------------|------|
| `ql1 ↔ ql2` | 3744 | **0** | 无害（贴边） |
| `ql4 ↔ p12` | 3042 | 1560 | **有害** |
| `ql3 ↔ p10` | 1989 | 1989 | **有害** |

**从"不可分"变为"完全可分"**，零容忍判据由此得以成立。

### D5-R4：溢出分级（含安全裕度）

**决策**：三级判定，**不一刀切**。

| 条件 | 判定 | 依据 |
|------|------|------|
| 内容跨度 ≤ 1.0× page | PASS | — |
| 1.0× < 跨度 ≤ 硬失败线 | **WARN** | E6：导出按内容裁剪，无实际危害 |
| 跨度 > 硬失败线 | **FAIL** | 官方 issue 实证：超大幅溢出会被真实裁切 |

**裁决：H 侧不得采用调研建议的 1.0× 作硬失败线**。实测 15 张真实图：W 比 0.85~1.15、H 比 0.53~0.97，其中 6-1 的 H 比已达 **0.97**、7-1 与 9-1 达 **0.95**——正常图逼近该线，一旦越线即硬失败会造成大面积误伤。硬失败线须明显大于 1 以保留裕度，具体取值见 `01-layout-algorithm-design.md`。

**根本解**：画布尺寸由内容 bbox 反推（`pw = snap(content_w + MARGIN)`），使溢出在生成阶段**结构性不可能发生**。

### D5-R5：几何完整性校验优先级最高

**决策**：`x`/`y`/`width`/`height` 的字面值为 `"None"`/`"nan"`/`"null"`/空/非数值/缺失 → **error，且优先级高于重叠检测**。

**理由**：它是唯一一类**直接产出废品**的缺陷（3-1 的 PNG 只有 325px），而重叠/对齐只是降低美观。且现有任何检查都拦不住它——`ET.parse()` 完全通过。

**配套的计数口径裁决**：校验器必须**同时输出两个数**——`vertex_total`（所有 `vertex="1"`，实测全库 **376**）与 `vertex_geometry_valid`（四个几何值均可 `float()`，实测 **370**）。**二者之差 6 恰是 3-1 的六个损坏顶点，该差值本身即最高优先级告警信号**。只报一个数会让此类损坏隐形（编排器前期采用的 366 单一口径正是把这 6 个坏点静默吞掉，导致 3-1 各项指标显示为"完美"的空值）。

### D5-R6：两级门禁，源文件层先行

**决策**：第 1 级 `drawio_layout_validator.py`（读 `.drawio`）→ 第 2 级 `figure_gate.py`（读 `.png`）。**必须先跑第 1 级。**

**理由**：PNG 层的诊断具**误导性**。3-1 在 figure_gate 报的是"宽度 325px 不足"，Agent 若照此提示去加大导出 scale，只会得到 650px 的同样残缺的图。**真因只在源文件层可见。**

校验器**不嵌入** figure_gate（三条理由：figure_gate 在 Pillow import 失败时直接 exit 1 而校验器是零依赖；独立脚本可只读先上线；figure_gate 刚被 D3 三次改动，不动它风险最低）。

### D5-R7：`routing=libavoid` 是错误写法

**决策**：`routing=libavoid` **不是 mxCell style 属性**（官方 style-reference 中该键出现 0 次，写进 style 会被静默忽略），它是 CLI 参数 / JSON layout 配置项。

此前那份 SCIF 补救方案（`架构图重制方案-2026-07-29.md` §1.2）明文写了 `ROUTING = "libavoid"` 并注释"设为 libavoid 让 draw.io 自动避障路由边线"——**属需要在 D5 中显式纠正的错误**，否则会被后续实施照抄。

### D5-R8：`pageWidth="960"` 冲突处置

`chart-quality-constraints/03-interface-design.md:473` 规定 drawio `pageWidth="960" pageHeight="720"`，而 SCIF 15 张真实产物用的是 1200~1660。

**决策**：D5 **显式取代**该条固定值，改为"由内容 bbox 反推"。理由：固定画布尺寸正是溢出的制度性根源——内容一旦超过 960 就必然溢出，而实际架构图几乎全部超过。此处**不是可回避的重复定义，是数值直接冲突**，必须明确取舍而非并存。

### 8.3 D5 的结构性空白：缺少"渲染后视觉核验"层

**这是本次对标最重要的发现。**

D5 现有 11 项判据**全部是基于坐标与尺寸的静态几何检查**（ink-box、overflow、对齐、拓扑）。而**三个竞品中有两个**都明确要求"实际读回渲染结果核验"。excalidraw-skill 的表述最直接：

> 语法有效不等于视觉正确。

D5 无法覆盖的失效类型（静态几何检查在原理上看不见）：

| 失效类型 | 为何静态检查看不见 |
|---------|------------------|
| 文字被容器截断 | ink-box 是**估算**；真实字体度量、字重、字距不同 → 估算合规但渲染溢出（对应 M-1 假阴性） |
| 箭头穿越组件框 | D5 **完全不校验边路由**（131 条边的几何一律未检查） |
| 半透明填充下的箭头透视 | 属渲染层，坐标层不可见 |
| 字体缺失导致的豆腐块 | 与坐标无关 |

**处置裁决**：确认为**已知空白，本期不认领**，理由与诚实标注如下：

1. **可行性受限**：读回 PNG 做视觉核验需要多模态读图能力，而该 skill 明确要跨模型运行（`model-profile` 有 Tier A/B/unknown 分档，Tier B 为 DeepSeek V4）—— **不能假定运行时具备读图能力**。竞品把它写为"可选步骤"（fireworks 原文即"若运行时可读图"）正是同一约束的体现。
2. **但可以做一件确定性的事**：**PNG 尺寸合理性反查** —— 若导出 PNG 的宽/高与 `.drawio` 内容 bbox 的比值显著偏离基线（实测该比值恒定在 2.02~2.13，见 07 号 §D），说明渲染结果与源文件不一致。这能以零依赖捕获 3-1 类灾难（325px vs 预期 ~2800px，比值 0.23 vs 基线 2.05）。**建议纳入 B1**，作为视觉自查的最低成本替代。
3. **边路由校验（箭头穿框）是真实缺口且技术上可做**（AABB vs 线段相交，纯标准库），但需要解析 `mxGeometry` 的 `Array as="points"` 与隐式路由 —— draw.io 的隐式正交路由**不在文件中显式记录**，只有渲染器知道。故仅能校验**显式 waypoints**，覆盖不全。**列为 B6 候选，本期不做。**

### 9.4 L-5 就地定案：压缩格式 `.drawio`

**原为悬空的两难，现定案：**

| 决策 | 取值 |
|------|------|
| 默认行为 | **解压后校验**（`base64` + `zlib.decompress(data, -15)` + `urllib.parse.unquote`，纯标准库，已实测可行） |
| CLI 选项 | `--on-compressed {decompress,fail,skip}`，默认 `decompress` |
| `skip` 的约束 | 使用 `skip` 时**必须**在 JSON 报告中登记被跳过的文件清单，且 exit code 记为 **2（部分校验）** 而非 0 |

**理由**：判 fail 会误伤正当的人工编辑（draw.io 一经打开另存即压缩）；判 skip 则"打开另存一次"成为零成本永久豁免路径。**解压是唯一既不误伤又不留后门的选项**，且技术上完全可行 —— 此前把它当"两难"是因为没意识到解压成本极低。

### 9.5 C-3：ink-box 假阴性使零容忍静默失效 → **已修复（且证实审查指控成立）**

**双向标定证实了缺陷**（01 号 §3.3.3）：初版 ink-box 在 3 个有害重叠对中**漏报 2 个，假阴性率 67%**。

四项修订：

1. **三态判定取代二态**：AABB 相交是**必要条件**，ink-box 相交是**确认有害的充分条件**，二者之间的灰区判 **WARNING 而非 PASS**。
2. **安全膨胀系数 `INK_INFLATE = 1.15`**。澄清审查提到的"方向反了"：`min(cell.w, raw)` 的钳制本身**正确**（墨迹不可能超出盒子），真正缺陷是 `raw` 被低估时钳制会把低估值原样保留 → 正解是**先膨胀 raw 再钳制**。加膨胀后 2 个漏报对全部重新捕获。
3. **`<br>`/`</div>`/`</p>` 转换为换行符**而非剥除。实测证明误差不对称：剥除会使宽度高估（保守）但**行数算成 1 行 → 高度低估 → 纵向漏报**。
4. **中文宽度按码位分段**：采用 `unicodedata.east_asian_width()`（审查正确指出这是标准库现成工具），W/F 计 1.00×fs、A 计 0.85×fs、其余 0.55×fs。

**诚实标注**：`1.15` 在同一批 7 对样本上标定，存在过拟合风险（新增局限 M-8）。

## 10. 方案对比：B4/B5 全 IR vs 确定性重排（D5-17）

> **本节位置说明**：第二轮审查 C-C7 指出"中间方案未被评估"，且要求补入 00 号。此处给出对比与决策程序；**不在本轮拍板**（06 号 §3.3 已定决策程序）。

### 10.1 三方案对比

| 维度 | **A. 现状**（Agent 写坐标，无干预） | **B. 确定性重排**（中间方案） | **C. B4/B5 全 IR** |

### 10.2 关键论点

**支持 B（中间方案）**：
1. **D5-12 已订正核心物证归因** —— `x="None"` 是脚本 bug，**G1 输出校验即可根治，不需要 IR**；
2. **C 方案的 manual 逃生舱直接违背其自身核心承诺**（D5-13），而 B **结构上不产生该矛盾**；
3. B 规避 L-3（IR 限表达）、M-3（模式覆盖率未知）、W-6（forced manual 放宽纪律）三条局限；
4. B 同样把修复算子换成确定性的 —— **这才是 D5-R1 真正想解决的问题**。

**支持 C（全 IR）**：
1. 只有 C 能做到"故障在**输入端**不可表达"（B 是事后校验+重排，故障可先产生再被修）；
2. C 的坐标全程公式生成，网格对齐恒 100%、溢出结构性不可能（实测 12/12 形态达成）；
3. B 的重排可能**破坏 Agent 的有意布局**（如刻意的非对称强调），C 则不存在"Agent 布局意图"这一概念。
