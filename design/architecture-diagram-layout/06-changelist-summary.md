## 3. 方案对比：B4/B5 全 IR vs 确定性重排（D5-17）

### 3.1 三方案对比

| 维度 | **A. 现状**（Agent 写坐标，无干预） | **B. 确定性重排**（中间方案） | **C. B4/B5 全 IR** |
|------|----------------------------------|---------------------------|-------------------|
| Agent 产出 | `.drawio`（含坐标） | `.drawio`（含坐标） | IR JSON（**无坐标**） |
| 校验失败后的修复算子 | **LLM 重算坐标**（不可靠） | **确定性脚本重排** | 确定性生成器 |
| 语义表达力 | 完整 | **完整** | 受五种模式枚举限制 |
| 是否需要 manual 逃生舱 | — | **否**（无 `layout_mode` 概念） | **是**（→ C-C2 矛盾） |
| 能否防住 `x="None"` | 否 | **能**（G1 校验 + 重排覆盖） | 能（schema 禁止） |
| 实施成本 | 0 | **中**（重排脚本，复用 §2 布局公式） | **最高**（IR schema + 生成器 + Agent 改造） |
| 对现有产出的兼容 | — | **完全兼容**（仍是 `.drawio`） | 不兼容（Agent 产出形态变更） |
| 引入的新风险 | — | 重排可能破坏 Agent 的有意布局 | manual 逃生舱、IR 表达力损失、模式覆盖不足 |

### 3.2 关键论点

**支持 B（中间方案）的证据**：
1. **D5-R1 的核心物证归因错误**（C-C1）——`str(None)` 是脚本 bug，用 **G1 输出校验**即可根治，**不需要 IR**；
2. **C 方案的 manual 逃生舱直接违背其自身核心承诺**（C-C2），而 B 方案**结构上不产生该矛盾**；
3. B 保留完整语义表达力，规避 L-3（IR 限制表达）、M-3（模式覆盖率未知）、W-6（forced manual 放宽纪律）三条局限；
4. B 同样把修复算子换成确定性的——**这才是 D5-R1 真正想解决的问题**。

**支持 C（全 IR）的证据**：
1. 只有 C 能做到"3-1 类故障在**输入端**不可表达"（B 是事后校验+重排，故障可以先产生再被修）；
2. C 的坐标全程由公式生成，网格对齐率恒 100%、溢出结构性不可能（实测 12/12 形态达成）；
3. B 的重排可能**破坏 Agent 的有意布局**（如刻意的非对称强调），而 C 从一开始就不存在"Agent 的布局意图"这一概念。
